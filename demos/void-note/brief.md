# Brief — void-note (회의 녹음 앱, iPhone)

## 레퍼런스 소싱 (0단계)
이 세션은 비대화형이라 클라이언트에게 반응을 받을 수 없었다. 그래서 질문 대신 PRD §3의 "사용자들의 상황" 문장 자체를 반응 원문으로 취급했다. 외부 레퍼런스 앱 조사는 하지 않았다(**조사 안 함**). 기존 앱에 대한 지식(클로바노트·Otter·티로·iOS 음성 메모)은 기억 기반이라 미검증이다.

## 상황 문장 → 역추출한 판단기준
| PRD 원문 | 뽑아낸 기준 |
|---|---|
| "앱 아이콘을 찾고 여러 단계를 누르는 사이 앞부분을 놓칩니다" | 시작은 앱 밖(잠금 화면·제어 센터·위젯)에서 탭 1회. 앱 안 시작 버튼은 보조 |
| "녹음 끄는 것을 자주 잊습니다" | 종료는 사용자 기억에 의존하지 않는다. 경고는 앱 밖(Live Activity·알림)에도 나온다 |
| "화면을 오래 들여다보고 싶지는 않다" | 녹음 화면은 1초 판독: 시간·소리·자막 3가지만. 글자 크게, 대비 높게 |
| "무엇이 어디로 나가는지 눈으로 보고 싶다" | '어디로'는 전송 기록 화면에만 두지 않고 목록·상세·설정 어디에서나 한 줄로 보인다 |
| "실패했다면 무엇을 하면 되는지" | 실패 문구는 ① 데이터는 기기에 있음 ② 다음 시도 시각 ③ 사용자가 할 일 1개 순서 |

## 명시적 가정 로그 (이렇게 가정했습니다)
- 회의 제목은 시작 시각 기반 자동 제목("오후 2시 2분 회의"). 사용자가 상세에서 고칠 수 있다. 앱이 요약해 제목을 짓지 않는다.
- 무음 자동 정지 시 마지막 무음 구간은 잘라 저장한다.
- 말소리가 없는 회의는 회사로 전송하지 않는다.
- 자동 재시도 간격은 15분 → 30분 → 45분 … 으로 늘어난다(더미 값).
- 음성 인식 모델은 "나중에"를 누르면 녹음은 되고, 변환은 모델을 받은 뒤 시작한다.
- 변환은 앱을 닫아도 이어진다(iOS 백그라운드 작업 가정).
- 전송 본문은 제목·시작 시각·길이·원문 텍스트만. 오디오·위치·기기 식별자는 보내지 않는다.
- 모델 다운로드 호스트는 huggingface.co 로 가정했다(미검증). 회사 주소는 가상(hooks.hangyeol.co.kr).
- 화면 기준 393×852pt (iPhone 15/16). 라이트 테마가 기본, 녹음 중 화면만 어두운 테마(책상 위에서 눈부심 없이 곁눈으로 보게).
- 시스템 UI(잠금 화면·제어 센터·Dynamic Island)는 iOS 실제 동작을 모사한 목업이며 정확한 OS 크롬은 근사다.

- Spacing 4pt 그리드: 4·8·12·16·24·32
- 타이포 6종: display 56 / title 28 / head 20 / body 16 / sub 14 / cap 12 (숫자는 tabular)
