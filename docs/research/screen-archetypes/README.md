# 화면 종류별 구조 유형 — 국내 서비스 화면 533장에서 묶기

이슈 #56의 1~2단계(조사·분류) 결과다. 하네스 반영(3단계 이후)은 이 표를 검토한 뒤에 한다.

## 분류

`classify.py`가 칸 이름의 위치로 유형을 정한다(위에서부터 첫 규칙). **서로 다른 앱·사이트 3개 이상**에서 나온 것만 유형. `python3 classify.py [--src=store|mweb] [--miss]`.

규칙에서 배운 것:
- **맨 위 검색창은 유형을 가르지 않는다.** 웹·앱 홈 대부분이 검색창으로 시작한다 — 홈에서는 머리말로 보고 뺀다(처음 규칙은 이 때문에 진열형을 찾기형으로 빨아들였다).
- 상품 격자는 2열만이 아니다 — 웹은 3열(무신사·번개장터·중고나라)이 흔하다.

## 읽을 때 주의

- **도메인보다 하는 일로 갈린다.** 한 앱이 탭마다 다른 유형이다(11번가: 찾기·진열·현황).
- **찾기형과 진열형의 경계가 흐리다.** 쇼핑 홈 상당수가 카테고리 격자와 진열 줄을 둘 다 가진다. 재라벨 불일치도 여기 몰렸다 — 하네스에 넣을 때 구분 기준(첫 화면에서 무엇이 먼저·크게 오나)을 분명히 하거나 한 유형의 두 변형으로 둔다.
- **지도·피드는 홈보다 목록 유형이다**(지도+목록 13, 카드 피드 31).
- **현황형·일정형 홈은 스토어에서만 나왔다** — 금융·가계부·캘린더는 모바일 웹이 거의 없다(로그인 뒤 화면).
- **입력·결과는 표본이 작고(77장) 홍보 화면뿐이다.** 실제 화면 확인이 안 된 유형이다.
