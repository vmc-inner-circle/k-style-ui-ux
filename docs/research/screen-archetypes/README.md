# 화면 종류별 구조 유형 — 국내 앱 89개 스토어 화면에서 묶기

이슈 #56의 1~2단계(조사·분류) 결과다. 하네스 반영(3단계 이후)은 이 표를 검토한 뒤에 한다.

## 방법

1. `market.py`로 도메인 19개 × 키워드 2개(아래), 도메인마다 평점 수 상위 5개 → 고유 앱 89개(겹침·무관 앱 제외), 스토어 스크린샷 시트 95장. 시트는 커밋하지 않는다(16MB, 같은 명령으로 다시 받는다).
2. 에이전트 8개가 시트를 나눠 보고, 폰 화면 안이 읽히는 스크린샷마다 `kind`와 위→아래 칸 순서(`slots`, 정해진 어휘)를 적었다 → `labels/*.out.json` (화면 465장).
3. `classify.py`가 칸 위치 규칙으로 유형을 정한다(위에서부터 첫 규칙). **서로 다른 앱 3개 이상**에서 나온 것만 유형으로 인정 → `archetypes.json`.

```
패션 쇼핑·옷 쇼핑몰 / 장보기·새벽배송 / 인테리어·가구 쇼핑 / 숙소 예약·호텔 예약 / 음식 배달·배달 주문 /
택시 호출·대리운전 / 송금·은행 / 중고거래·동네 생활 / 익명 커뮤니티·직장인 커뮤니티 / 운동 기록·홈트레이닝 /
필라테스 예약·원데이 클래스 / 할일 관리·캘린더 일정 / 전자책·웹소설 / 여행 일정·투어 액티비티 /
병원 예약·비대면 진료 / 부동산 매물·원룸 월세 / 맛집 리뷰·식당 예약 / 가계부·지출 관리 / 온라인 강의·영어 학습
```

## 읽을 때 주의

- **도메인보다 하는 일로 갈린다.** 같은 커머스라도 11번가는 찾기·진열·현황이 탭마다 다르고, 배민(찾기)과 컬리(진열)도 다르다. 한 앱이 여러 유형에 걸리는 건 탭 첫 화면마다 유형이 달라서다.
- **지도는 홈이 아니라 목록 유형이다.** 홈 지도형은 2개뿐이지만 목록의 지도+목록은 13개.
- **피드는 홈보다 목록에서 나온다**(홈 3개 중 분명한 건 당근뿐, 목록 카드 피드는 31개).
- 스토어 스크린샷은 홍보용이라 실제 첫 화면과 다를 수 있다. `conf: low` 라벨도 섞여 있다(분류에서 빼지 않음).
- 분류 규칙은 칸 이름의 위치만 본다 — 경계 사례(예: 현황 카드를 얹은 진열형)는 첫 규칙 쪽으로 간다.
