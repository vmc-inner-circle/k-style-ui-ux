## 3. 토큰 · 기초 단위 · 부품 — 구조 검토

레퍼런스 DESIGN.md는 모두 같은 순서로 쓰여 있다: 색 역할(상태색 · 어두운 모드 포함) → 이름 붙은 글자 단계(크기 · 굵기 · 줄간격 · 자간 묶음) → 간격 → 모서리 단계 → 그림자 → 부품(상태별) → 하지 말 것.

**잘 돼 있는 것**
- 색 역할은 레퍼런스와 거의 같다(looks.js: bg · surface 1~3 · border · text 3단계 · primary 묶음 · focus · 상태색 4종 + 연한 변형).
- 간격은 4px 단위 10단계로, 토스 · SEED와 같다.
- 부품 CSS에 색 hex를 직접 쓴 곳은 0건이다.

## 4. 프리셋 형식 v2 — 최소안 (지금 칸에 다섯 개만 더함)

```json
{ "id": "toss", "bg": "#F2F4F6", "ink": "#191F28", "font": "pretendard", "swatches": [ … ],
  "radius": { "control": 16, "card": 20 },
  "card": "fill",
  "weight": { "head": 700, "button": 700 },
  "status": { "danger": "#F04452" },
  "body": 15 }
```

- `radius.control`: 숫자 또는 `"pill"`. 지금의 `shape` 4종을 대체한다(`shape`는 예전 이름으로 남김).
- `card`: `fill`(회색 바탕 위 흰 판) · `line`(선으로 나눔) · `shadow`. 그림자 진하기는 이 값에서 정하고, 어두운 모드에서는 자동으로 올린다.
- `weight`: 글꼴 세트의 굵기를 덮어쓴다.
- `status`: 없으면 공통 상태색을 쓴다.
- `body`: 본문 크기 15 · 16 · 17.
- 일부러 뺀 것: 자간(글꼴 세트에 둠) · 움직임 · 눌림 방식 — 효과가 작다.
- 데이터 출처: ko-design-md는 브랜드마다 `.tokens.json`이 있다. 국내 4개는 **가져오는 스크립트**로 채울 수 있다(손으로 옮기지 않기).

**P2 — 대비 자동 보정 + 검사** (`scripts/looks.js` · `scripts/lint.js`)
- 기준: 글자는 바탕 · 카드 둘 다에서 **4.5 이상**. 보조 글자(text-2)는 흐린 글자보다 한 단계 진하게 **6 이상**. 연한 배지 · 연한 버튼 글자도 4.5 이상.
- 보정(`lookTokens` · `statusTokens` · `swatchTokens`)
  - 모자라면 본문 글자 쪽으로 진하게 섞는다(`atLeast`).
  - 버튼 글자는 흰색이 4.5 이상이면 흰색, 아니면 흰색 · 진한 글자 중 큰 쪽.
  - 우리가 만든 분위기(exact 아님)에서 둘 다 4.5가 안 되면, 흰 글자가 4.5가 될 만큼만 버튼 색을 깊게 한다(아침 햇살 청록 #1F8A84 → #1E847F, 테라코타 #C8553D → #C4533C).
  - **레퍼런스(exact)는 그 앱의 흰 버튼 글자를 3 이상까지 지킨다**(WCAG 큰 굵은 글자 기준). 예전 하한은 2.2였다.
- 검사: `looks.audit(L, sw)` → lint가 PRD 맞춤 분위기와 레퍼런스 21개 × 버튼 색을 전부 잰다.
  - 보정이 깨지면 FAIL이다(일부러 흐린 본문을 넣어 잡히는 걸 확인함).
  - 레퍼런스 흰 글자 허용(24곳)과 "버튼 색을 글자로 쓸 때 4.5 미만"(54곳)은 경고 한 줄씩으로 모은다.
