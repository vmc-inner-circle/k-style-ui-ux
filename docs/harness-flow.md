# 하네스 플로우 — PRD를 넣으면

사용자는 **두 번** 개입합니다(한도 5회 — 완성본을 더 고칠 때만 세 번째부터). 사람 결정(2026-10-21): 초안 보드 없이 시안 보드에서 바로 완성본. 시간은 셀프 테스트에서 잰 값이에요.

**시작**: 새 세션에서 PRD만 넣습니다. 예: `/design-harness prd/family-trip.md`, 또는 PRD 내용을 그대로 붙여넣기. PRD 파일은 고치지 않고 그대로 넣어요. **(개입 1)**

## 1턴: PRD → 시안 캔버스 (약 5분)

1. **PRD 분석 — 걸음 다섯 개로 나눠 씁니다**(칸과 걸음은 `packages/core/schema/schema.json`이 정본):
   - **I 의도**: 휴대폰/컴퓨터, 유저스토리, 역할(보기만 하는 역할은 글자 크게), 상태 어휘와 누가 볼 수 있는지, 화면 말 사전, 공통 사실 → `node scripts/schema.js runs/<p> --step intent`
   - **L 화면 목록**: 화면(오류·완료 상태 포함), 구역·단계 → `--step list`
   - **S 화면 하나**: 화면마다 답 하나 · 나머지 · 뺀 것, 정책, 흐름·갈래와 조건 분기
   - **C 시안**: 아래 2번
   - **P 프리셋**: 기준어 셋 · 바탕 톤 · 대표색 · 글꼴 · 글자 크기 · 간격 → `--step full`(S · C는 따로 검사 문이 없고 여기서 함께 봐요). 색은 하네스가 프리셋에서 계산해요
2. **시안 4개 정하기**: 과감함 1 · 4 · 7 · 10단계(무난 → 과감). 레이아웃 패턴 21개(`packages/core/layouts/layouts.json`)에서 서로 다른 것을 고르고, 4단계부터는 패턴 두 개를 섞어요. 꾸밈(배경·판 모양·제목·모서리·간격·글꼴·아이콘·색 쓰는 방식·그라데이션)은 `scripts/dress.js`가 단계에 맞춰 채워요.
3. **시안 화면 만들기**: 시안마다 메인 화면 5~6장, 작업 묶음(팩) 하나에 3장씩 조립 에이전트 20개가 동시에(합쳐 약 2분 40초).
4. **검사 → 브라우저에 자동으로 띄우기**: 시안 캔버스(시안마다 한 줄, 화면은 전체 길이로 보기만 · 끌기·휠로 이동 · ↑↓ 다음 안). 레이아웃은 추천하지 않아요.

→ **사용자**: 시안 하나를 고르고(오른쪽 위 '테마' · '컬러' · '폰트'로 색 · 글꼴 · 글자 크기도 바로 바꿔 보며), 고른 시안의 화면은 '자세히 보기'에서 바로 고친 뒤(끌어서 순서 · 두 번 눌러 글자 · A− A+ 크기 · ✕ 빼기) 복사해서 붙여넣기 **(개입 2)**

## 2턴: 고른 시안으로 완성본 · 바로 제출

- 고른 시안의 메인 화면은 그대로 옮기고, 시안 보드에서 직접 고친 것은 `scripts/edits.js`가 AI 없이 바로 반영해요. 나머지 화면은 같은 모양으로 새로 만듭니다.
- 시안을 고르며 적은 말은 한 줄마다 `node scripts/feedback.js "<의견>"`로 의견 사전(`packages/core/feedback/glossary.json`) 줄을 찾아 `board.feedback`에 해석을 기록한 뒤 반영해요.
- **완성본**: `index.html` 입구 + 화면별 완성본 페이지(버튼을 누르면 다음 화면으로, 모바일은 휴대폰 크기, 스크롤하면 판이 나타나고 큰 제목이 접힘).
  - **사용 흐름**: 디자이너 보드처럼 구역(가입·홈 …)마다 화면이 쓰는 순서대로 나란히, 화면 아래 검은 상자에 그 화면의 규칙. 초록 화살표는 조건이 갈리는 곳에만.
  - **흐름 재생** · **화면 전체** · **디자인 시스템**.
  - **화면 디자인**: 아무 요소나 골라 의견을 남기거나 직접 고쳐요(위쪽 '의견 보내기'로 복사).
  - **테마 · 컬러 · 폰트**: 어느 페이지에서든 바로 바꿔요 — 고른 색은 그 브라우저에 기억돼요.
- `submissions/srlee0408/`에 결과물, `prompt-log.md`, `elapsed.txt`를 복사합니다. 제출 확인은 묻지 않습니다.

→ **사용자**: 할 일 없음. 더 고칠 게 있을 때만 '의견 보내기' 글이나 고칠 점을 붙여넣기 **(개입 3, 선택)**

## 3턴(선택): 완성본 고치기

- 사용자가 의견을 붙여넣었을 때만 생깁니다. 직접 고친 줄은 `edits.js`가 먼저 반영하고, 나머지 의견은 작은 수정은 가벼운 모델(haiku), 배치를 바꾸는 수정은 sonnet이 고칩니다. 반영해서 다시 제출하고, 더 묻지 않고 끝냅니다. 남는 개입은 더 고칠 때와 사고 났을 때를 위한 여유분이에요.

---

**예외**: PRD가 애매해서 잘못 짐작하면 화면 대부분을 다시 만들어야 하는 경우에만, 1턴 전에 객관식 질문을 한 번 합니다(3개 이하). **휴대폰용인지 컴퓨터용인지 PRD에 없으면 이 질문에 꼭 넣어요**(웹·모바일은 화면 부품이 달라요). 그러면 여유분이 하나 줄어드므로 정말 필요할 때만 해요.

**화면 미감**: 디자이너 기준으로 자동 보정해요 — 본문 글자는 순수 검정 대신 눈이 편한 진회색, 번짐·그라데이션은 버튼 색의 이웃 색으로만, 강조색 큰 꾸밈은 한 안에 둘까지, 글자 크기는 정해진 단계만·왼쪽 정렬. 화면은 NN/g 사용성 10원칙 기준으로 조립하고 lint가 검사해요.
